# Spectral Filtering Accuracy

PyStormTracker currently uses `ducc0` for spherical harmonic transforms in spectral filtering, regridding, and kinematic derivatives. SHTns is not a runtime backend or package dependency. Its results below are retained as a historical comparison; a standalone SHTns-versus-ducc0 benchmark script is planned.

## Methodology

The recorded comparisons use root mean square error (RMSE), relative error, and Pearson correlation for ERA5 mean sea level pressure and wind data. Reference fields generated by `tests/data/era5/process_era5.ncl` are checked in under `tests/data/era5` and treated as the expected outputs for ducc0 spectral and kinematic integration tests.

Two spatial resolutions are tested:
- **2.5°x2.5°**: A low-resolution grid (73x144) where T42 truncation (requiring ~85 latitudes) results in aliasing.
- **0.25°x0.25°**: A high-resolution grid (721x1440) where T42 truncation is alias-free.

## Spherical Harmonic Transform (SHT) Engines

### 1. ducc0 (Current)
`ducc0` is the production spherical harmonic transform engine.

*   It is installed as a core dependency.
*   It provides two-dimensional spherical harmonic analysis and synthesis on Clenshaw-Curtis and Gauss-Legendre grids, pseudo-analysis for reduced Gaussian grids, arbitrary-point synthesis, spin-1 vector transforms, and HEALPix geometry used by this project.
*   The tables below report measured differences from versioned NCL reference fields.

### 2. SHTns
SHTns was a spherical harmonic transform engine in earlier versions and was used in the recorded comparison work, but it has been removed from the package code and dependencies.

*   Existing scalar-filter and kinematic-derivative measurements are retained for context.
*   They are not run by the current test suite.
*   A planned standalone benchmark script will install or locate SHTns separately and run the SHTns and ducc0 engines on identical fields.

## Historical SHTns Polar-Optimization Result

For the recorded 0.25° SHTns run, disabling the polar optimization threshold (`polar_opt=0.0`) produced:
- **Accuracy**: RMSE difference is negligible (~10⁻¹⁵ Pa).
- **Performance**: The default setting is approximately 1.25% faster.

This option does not apply to the current ducc0 implementation.

## Summary

The current code and integration tests use ducc0. At 0.25° resolution, the recorded ducc0 vorticity RMSE against the NCL field is `1.74e-14 s^-1`; scalar-filter errors are listed above. The planned comparison harness should reproduce these measurements and record software versions, compiler settings, truncation, thread count, and hardware before the historical SHTns timing claims are updated.
